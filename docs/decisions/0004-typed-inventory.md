# 决策 0004：以物品标识和数量表示库存

- 状态：已实现，待人工验收

## 背景

阶段 2 的背包与 stash 是整数，只能表达总数，不能表达物品种类。阶段 3 需要在保持成功/失败结算行为的同时，支持不同物品；如果同时保留可写总数与明细，就必须在每次拾取、结算、死亡中同步两份状态。

## 决策

使用不可变 `ItemStack(item_id, quantity)` 描述物品内容；标识是非空且无首尾空白的字符串，数量必须为正整数（布尔值和小数不接受）。`Inventory` 内部以标识映射数量，同类合并、异类独立，零数量条目删除。`entries` 返回不可变快照，避免界面修改库存。

`GameSession.backpack` 和 `Game.stash` 各有独立实例。旧总数名只保留为计算属性，不再接受赋值或构造参数。拾取先将内容加入背包，再标记拾取物已收集；成功状态转换时一次性转移所有种类到 stash，失败只清空背包。转移先构造目标合并结果再清空来源，禁止自身转移。

## 取舍与边界

- 不提供旧整数构造接口的兼容层；当前无存档或外部调用方需要迁移，仓库内调用点和测试同步调整。
- 库存没有容量、重量、装备属性或物品目录；暂时接受符合格式的任意标识。显示直接使用标识，后续再引入展示名称。
- 地图仍只有一个 `scrap` 拾取点，多种类正确性先通过测试验证，不在一次改动中扩展地图结构。
- 转移是当前单线程、无容量限制模型内的操作，不是数据库事务；以后增加容量或持久化时需要重新设计失败恢复。
- stash 仍只在内存中跨局保留，关闭程序清空。
