# 决策 0003：基础战斗计时与终局结算顺序

- 状态：已实现，待人工验收

## 背景

加入玩家受伤后，仅让生命值归零不够：需要明确是否还能移动、同帧能否撤离、携带物如何处理，以及下一局是否继承攻击计时。攻击若按每帧扣血，伤害还会随帧数变化。

## 决策

- 玩家初始 100 血，复用已有 `Health`，但双方各自拥有独立实例。
- 敌人近距离攻击：中心距离不超过 64 像素时连续计时，每满 1 秒造成 20 伤害。离开范围取消计时，再进入重新准备。当前追踪停止距离为 56 像素，在攻击范围内。
- 用秒累计而不是每帧扣血，保留不足一个攻击间隔的余量；长帧计入完整攻击次数。
- 一帧顺序为：已有死亡检查 → 玩家移动/瞄准/发射 → 弹丸命中 → 存活敌人攻击 → 玩家死亡检查 → 敌人追踪 → 拾取 → 撤离。
- 因此同帧先击败敌人可阻止其反击；同帧受到致命伤则不能拾取或成功撤离。
- 死亡进入 `FAILED`，清空本局携带物并冻结局内状态，不改变已有 stash；成功仅结算一次。两种终局都可按 `R` 创建全新一局。

## 原因与代价

固定顺序让行为可解释、可测试；先攻击再追踪避免将远处追赶的整个时间步长计为近身准备。范围判断按帧采样，不是连续物理模拟，因此刚追到攻击范围的敌人要到下一帧才开始计时。长时间卡顿时已在攻击范围内的玩家可能一次看到多次伤害。当前没有护甲、无敌帧、受击打断、敌人投射物、存档或死亡掉落回收。

## 验证依据

- `tests/test_combat.py` 覆盖固定目标下不同帧数的攻击一致性、范围边界、跑开取消计时、死亡优先于拾取/撤离、历史 stash 保留及新局全部恢复。
- `tests/test_app.py` 在无显示环境覆盖成功和失败终局渲染。
- 当前完整套件 95 项测试通过；人工验收清单见项目计划。

## 重新评估条件

增加多敌人、远程攻击、障碍物或要求精确处理双方同时运动时，重新设计攻击调度和碰撞时间线；不要在未定义顺序的情况下随意交换更新调用。
