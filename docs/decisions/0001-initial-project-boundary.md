# 决策 0001：先验证撤离闭环

- 状态：已接受
- 日期：2026-09-02

## 背景

完整的撤离类游戏同时涉及移动、战斗、AI、物品、经济、地图和存档。一次实现过多系统会使失败原因难以定位，也无法判断 AI 生成内容是否真的可用。

## 决策

第一阶段只实现无战斗的撤离闭环：移动、拾取、撤离、局外保留和再次出发。游戏规则与渲染框架分离。

## 原因

- 它保留了参考玩法最关键的收益闭环。
- 每条规则都能用明确步骤和自动化测试验证。
- 后续战斗、AI 和经济系统可以逐个加入并观察影响。

## 代价

- 第一版不像完整游戏，展示效果有限。
- 前期需要花时间维护边界和测试，而不是快速堆叠内容。

## 重新评估条件

如果选定框架无法让领域逻辑脱离画面运行，或阶段 1 的测试成本明显高于收益，应重新评估模块边界。
