# 决策 0002：阶段 1 使用 Python 与 pygame-ce

- 状态：已接受
- 日期：2026-09-02

## 背景

项目目标包括学习 Python、软件架构和 AI 辅助开发。第一阶段只需要窗口、输入、简单绘制和碰撞，不需要完整编辑器或复杂 3D 管线。

## 决策

使用 Python 3.14 与 pygame-ce 2.5.8 实现阶段 1。游戏规则与 pygame 接口分离，使核心规则能够在无窗口环境中测试。

## 原因

- pygame-ce 官方包提供 Python 3.14 的 Windows 64 位 wheel。
- 框架足够薄，便于观察游戏循环、状态和依赖关系。
- 可以用 `SDL_VIDEODRIVER=dummy` 执行自动化窗口冒烟测试。

## 代价

- 缺少完整引擎的场景编辑器、动画工具和可视化资源管线。
- 项目变大后，需要自行维护更多工具和性能边界。

## 验证证据

- Python 3.14.7 和 pip 26.2.1 安装成功。
- pygame-ce 2.5.8 在 Windows 64 位环境安装成功。
- 两个 pytest 测试通过。
- 程序使用虚拟显示驱动运行三帧并以退出码 0 结束。

## 重新评估条件

出现以下任一情况时重新比较 pygame-ce 与完整游戏引擎：

- 关卡编辑耗时明显超过玩法实现。
- 动画、粒子或着色器需求成为主要工作量。
- Python 性能无法通过合理的数据结构或局部优化满足目标。
