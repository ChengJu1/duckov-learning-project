# 项目计划

## 最小可玩循环

第一版只验证以下闭环：进入小地图，移动，拾取一个物品，前往撤离点，结算并在局外看到该物品。

核心判断不是“内容是否丰富”，而是玩家是否能理解风险与收益，并愿意再次进入地图。

## 阶段 0：仓库和环境

状态：已完成（2026-09-02）

### 目标

- 建立 Git 仓库并推送到 GitHub。
- 记录范围、架构、决策和失败案例。
- 安装并验证 Python 开发环境。

### 验收标准

- `git status` 能正常工作且默认分支为 `main`。
- GitHub 能看到首次提交及全部基础文档。
- `python --version` 能输出确定的版本。
- 新开发者只看 README 就能知道项目目标、状态和下一步。

实际验证结果：Python 3.14.7、pygame-ce 2.5.8；2 个自动化测试通过，无界面三帧启动验证退出码为 0。

## 阶段 1：无战斗撤离原型

状态：已完成（2026-09-02）。

### 实现内容

- 一个固定大小的窗口。
- 一张简单测试地图。
- 键盘控制角色移动。
- 一个可以拾取的物品。
- 一个撤离区域。
- 一局开始、成功撤离和重新开始。
- 最小局外库存，用于证明撤离收益被保留。

### 暂不实现

- 枪械、伤害、敌人和复杂 AI。
- 随机地图、任务、商店和经济平衡。
- 联机、多线程服务器和账号系统。
- 正式美术、音效和动画。
- 大型数据库；第一阶段优先使用内存状态，持久化方案另行决策。

### 可执行验收标准

1. 启动程序后 5 秒内显示测试地图和玩家。
2. 玩家可以用明确记录的按键向四个方向移动，且不能离开地图边界。
3. 玩家接触物品后，物品从地图消失，局内携带数量增加 1。
4. 未拾取物品时进入撤离点不会凭空获得物品。
5. 携带物品进入撤离点后显示撤离成功，局外库存增加 1。
6. 开始下一局后，地图物品恢复，局外库存保持不变。
7. 至少有自动化测试覆盖“拾取”和“撤离结算”的纯逻辑。

自动验证结果：19 个测试通过；源码编译检查和三帧窗口冒烟验证通过。

人工验证结果：连续完成两局后 stash 按 0 → 1 → 2 增长；按 `R` 后玩家和物品恢复，stash 保留；进行中的一局不能被 `R` 重置。

## 阶段 2：基础战斗

状态：已完成。五个功能里程碑通过人工验收，阶段复盘与收尾回归已完成；证据和已知限制见 [阶段 2 复盘](stage-two-review.md)。

### 渐进范围

1. 鼠标瞄准方向。
2. 基础弹丸的生成、移动和地图外清理。
3. 一个静态敌人及最小生命值、伤害规则。
4. 简单敌人追踪移动。
5. 玩家生命值、敌人攻击和失败结算规则。

当前版本已实现第 1 至 5 项，不包含弹药、射速限制、装备或存档。玩家瞄准方向始终是从玩家中心指向鼠标的单位向量，因此鼠标远近不会改变瞄准线长度；鼠标恰好位于玩家中心时保留上一次有效方向。每次鼠标左键按下会从玩家中心沿当前瞄准方向生成一个定速弹丸，弹丸完全离开地图后被清理。成功撤离或死亡后，移动、瞄准、发射、敌人和弹丸状态均冻结。

敌人初始 100 血，每发命中造成 25 伤害，命中弹丸被消耗；四发击败后隐藏敌人并显示击败提示。死亡敌人不再参与命中判定或移动，生命值最低为 0。击败敌人不奖励物品、不影响撤离条件、不阻挡移动。新局重建敌人、恢复出生位置和满血并清空弹丸，stash 继续保留。

追踪范围：朝玩家中心直线移动，速度 90 像素/秒，中心距离 56 像素内停止，不后退、不推开玩家。移动按时间计算并限制单帧距离，斜向不加速、大时间步长不冲过停止位置；整个敌人保持在地图边界内。玩家主动进入停止范围或穿过敌人是允许的。暂不加入障碍物、寻路、视野或巡逻。

攻击与失败范围：玩家初始 100 血；中心距离不超过 64 像素时，敌人每连续准备 1 秒造成 20 伤害，跑出范围会取消准备。双方生命值不共用。死亡优先于同帧拾取与撤离，丢失本局携带物，已有 stash 保留。死亡或成功撤离均可按 `R` 恢复双方位置、生命值、物品、弹丸与攻击计时；进行中不能重开。橙色准备条、玩家血条、受伤闪红和失败文本提供反馈。

收尾自动验证结果：98 个测试通过；源码编译检查、三帧无界面窗口冒烟验证和 Git 空白检查通过。原有攻击、射击、追踪、死亡与撤离测试继续通过；新增实际出生配置的“成功 → 失败 → 成功”连续三局测试，在 30、60、120 帧模拟步长下均验证 stash 按 0 → 1 → 1 → 2 变化、重开恢复整局初始状态。无界面测试覆盖成功与失败画面。

鼠标瞄准人工验证结果：瞄准方向与固定线长正确；移动与瞄准可以同时操作；撤离冻结和新局恢复正常。

基础弹丸人工验证结果：单击发射、不自动连发、沿瞄准方向移动、越界消失，以及撤离后禁止发射均已通过。

静态敌人与伤害人工验证结果：用户确认本轮验收无问题，包含射偏不扣血、命中四次击败、存活敌人不阻止撤离，以及新局满血恢复和 stash 保留。

### 静态敌人与伤害验收清单（已通过）

1. 右上方出现红色静态敌人和血条，左上角显示 `Enemy HP: 100/100`。
2. 射偏不扣血；每次命中消耗弹丸，血量依次变为 75、50、25、0。
3. 第四次命中后敌人与血条消失，显示 `Enemy defeated`；继续射击不会被死亡敌人挡住。
4. 不击败敌人也能拾取和撤离；撤离后战斗状态冻结。
5. 按 `R` 后敌人满血重生、旧弹丸清空、物品恢复，stash 保留。

敌人追踪移动人工验证结果：用户确认本轮验收无问题，包括慢速追踪、接近停止与走远后恢复、击败与撤离后停止，以及新局出生位置/满血恢复和 stash 保留。

### 敌人追踪移动人工验收（已通过）

1. 红色敌人从右上方缓慢靠近玩家，血条跟随；玩家移动速度更快，能拉开距离。
2. 玩家站着不动时，敌人在附近停止，不反复穿过或折返；玩家走远后重新追踪。
3. 移动中仍可命中扣血、四发击败；击败后敌人消失，不再追踪。
4. 不击败敌人也能正常拾取和撤离，撤离成功后存活敌人也停止移动。
5. 按 `R` 开始新局，敌人回到右上方满血重生并重新追踪，stash 保留。

玩家生命值、攻击与失败结算人工验证结果：用户确认本轮验收无问题，包括近距离定时扣血、跑开取消准备、受伤反馈、击败后停止受伤、死亡丢失本局携带物且保留已有 stash、失败后重开恢复，以及成功撤离正常结算。

### 玩家生命值、攻击与失败结算人工验收（已通过）

1. 玩家初始 `Player HP: 100/100`，敌人靠近后橙色条增长，每约 1 秒扣 20 血，受伤时短暂闪红。
2. 在橙色条填满前跑出攻击范围，血量不减少；重新接近后需要重新准备。击败敌人后不再受伤。
3. 先拾取物品，再站着承受五次攻击：生命值归零、显示 `YOU DIED`，携带数清零，stash 不增加，移动与射击失效。
4. 死亡后按 `R`：玩家和敌人满血回到出生位置、物品恢复、弹丸清空；攻击不会继承上局计时。
5. 成功撤离一局后再死亡一局：已有 stash 保留；成功撤离后不再扣血，只有成功撤离才增加 stash。

## 阶段 3：物品与背包（进行中）

第一个里程碑“按物品种类记录库存”已通过与多物品地图的合并人工验收。`ItemStack` 记录物品标识与正整数数量，`Inventory` 按标识累计；局内 `backpack` 与局外 `stash` 各自拥有独立库存，总数从明细计算。拾取保留物品种类与数量，撤离按种类合并并清空背包，死亡只清空背包。新局保留 stash，不复用旧背包。

第一个里程碑实现时沿用一个绿色拾取点，默认 `scrap` ×1；用户于 2026-09-05 确认多物品版本无问题，两个里程碑已合并通过人工验收。

验收标准：同类物品累计、不同物品区分、重复拾取不生效；成功撤离只转移一次，死亡清空局内物品但不改变历史 stash；重开无局内残留，阶段 2 的行为回归继续通过。

自动验证结果：122 项测试通过，源码编译、三帧无界面窗口启动与 Git 空白检查通过。新增覆盖同类累计、不同类区分、非法标识/数量、移除不足、不可变快照、转移后无共享状态、多类跨局结算、死亡保留历史 stash。阶段 2 三局测试同时验证总数和 `scrap` 种类。

### 单拾取点版本的原验收清单（历史参考，以多物品验收为准）

1. 初始背包和 stash 都显示 `0 (empty)`；拾取后背包显示 `1 (scrap x1)`，物品消失且不重复拾取。
2. 成功撤离后背包显示 `0 (empty)`，stash 显示 `1 (scrap x1)`。
3. 按 `R` 开始下一局，背包为空、物品恢复、stash 保留；再成功带回一份后变为 `2 (scrap x2)`。
4. 后续一局拾取后死亡，背包清空，stash 的种类和数量不变；重开与战斗仍正常。

### 地图多物品拾取（已通过人工验收）

单局使用 `loot_items` 列表管理多个拾取点。地图配置为两份 `scrap x1` 和一捆 `wire x2`；废料绿色、电线紫色，均显示标识和数量。每处独立收集，同类合并，不同种类分别记录；只拾取部分物品也可撤离。新局重新创建全部拾取物，死亡清空所有携带类别，历史 stash 保留。

本轮验证：131 项测试通过，源码编译、三帧无界面窗口启动与 Git 空白检查通过。新增测试覆盖独立拾取、重复接触、同帧重叠拾取、空地图、部分撤离、多类成功/死亡结算、完整新局恢复；实际地图在 30/60/120 模拟帧率下收集全部物品并撤离通过。

人工验收以本轮地图为准：

1. 地图显示两处绿色 `scrap x1` 和一处紫色 `wire x2`，接触后对应物品与标签消失。
2. 全部拾取显示总数 4，明细 `scrap x2, wire x2`；回到已拾取位置不增加数量。
3. 撤离后背包为空，stash 保留对应种类和数量；下一局全部带回后累计为 `scrap x4, wire x4`。
4. 仅拾取一个点也能撤离；未拾取的物品不计入 stash。
5. 携带多种物品后死亡，背包全部清空，历史 stash 不变；按 R 后三处物品恢复。

人工验证结果（2026-09-05）：用户确认本轮无问题，包含各拾取点独立消失、分类数量正确、撤离转移与跨局累计、部分拾取可撤离、死亡保留历史 stash 及新局恢复。

### 最小背包容量（已实现，待人工验收）

默认地图背包容量 3，按各类物品数量总和计算，stash 不限容量。拾取采用整捆接收：空间不足时不修改库存、不标记收集，物品继续留在地上。底部显示空间不足提示，离开该拾取点后提示消失。重开恢复空的 3 格背包，死亡只丢失携带物。尚未加入拆分、丢弃、拖拽、装备、敌人掉落与存档。

验证结果：144 项测试通过，源码编译和 Git 空白检查通过。覆盖零容量、不限容量、满载拒绝、容量按件计数、释放空间后重试、转移失败双方不变、同帧拾取顺序、满载撤离/死亡和新局恢复。真实地图的三帧率测试已改为验证两份废料入包后拒绝整捆电线，原有不限容量多物品测试保留。

人工验收：

1. 初始显示 `0/3`，先拾取两份废料显示 `2/3`；接触电线时提示空间不足，电线仍在地上且背包数量不变。
2. 离开电线后提示消失，能够携带两份废料正常撤离。
3. 新局先拾取电线再拾取一份废料，显示 `3/3 (scrap x1, wire x2)`，另一份废料无法拾取；撤离后全部转入 stash。
4. 满载死亡只清空背包，stash 不变；重开恢复 `0/3` 和全部拾取物。

下一步根据容量验收结果确定背包物品操作的小任务。

## 当前假设

- 游戏采用俯视角、单机、键盘鼠标操作。
- 第一阶段只支持 Windows。
- Python 是主要语言，阶段 1 使用 pygame-ce；若后续内容工具或性能需求证明它不合适，再通过新的决策记录评估迁移。
- 参考游戏只用于学习玩法结构，不直接分发其素材、代码或商标资源。
- GitHub 仓库由用户手动创建，本地通过 HTTPS 远程地址连接。

## 实施前仍需确认

阶段 1 先采用纯 Python 与 pygame-ce。进入大量关卡编辑、复杂动画或着色器工作前，需要重新评估继续使用框架还是迁移到完整引擎。
